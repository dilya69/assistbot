# Личный помощник (Telegram мини-приложение)

Каркас: вход через Telegram, база, пять пустых вкладок и настройки с выбором оформления.

```
docs/                      мини-приложение (статика, можно на GitHub Pages)
supabase/migrations/       схема базы
supabase/functions/api/    серверная функция: проверка подписи Telegram и все запросы
supabase/functions/tick/   бот-планировщик: раз в минуту шлёт напоминания и сообщения о сменах
```

## Запуск по шагам

### 1. Репозиторий
Создай новый репозиторий на GitHub и залей туда содержимое этой папки.

### 2. Supabase
1. Создай новый проект Supabase.
2. SQL Editor: выполни `supabase/migrations/001_init.sql`.
3. Database, Extensions: включи `pg_cron`, затем выполни `002_cron.sql` (ночная очистка старых данных).
4. Edge Functions: создай функцию `api` и вставь код из `supabase/functions/api/index.ts`.
   В настройках функции отключи «Verify JWT», потому что вход проверяется подписью Telegram.
5. Secrets функции:
   - `BOT_TOKEN`: токен бота от BotFather;
   - `ADMIN_TG_ID` необязателен. Администраторов можно назначить в базе: `update users set role = 'admin' where first_name = '...';` после того, как они один раз откроют приложение.

### 2а. Планировщик (напоминания и сообщения о сменах)
1. Расширения `pg_cron` и `pg_net` должны быть включены.
2. Создай функцию `tick` из `supabase/functions/tick/index.ts`, «Verify JWT» отключи (доступ закрыт секретом).
   Секрет `BOT_TOKEN` тот же, что у `api`.
3. Выполни `supabase/migrations/004_scheduler.sql`: он создаёт секрет в Vault и задачу cron раз в минуту.
   Секрет создаётся внутри базы и нигде не показывается.
4. Проверка: в журнале ошибок (карточка администратора) не должно быть записей `tick`.
   Пробный запуск без отправки: POST на `/functions/v1/tick` с `{"dry": true}` и заголовком `x-cron-secret`.

Правила отправки:
- напоминание уходит в момент «время минус за сколько напомнить»; опоздавшее (тихие часы, сбой) уходит позже, но не позже чем через сутки;
- тихие часы (по умолчанию 23:00–08:00) и пауза задерживают напоминания, при включённом `quiet_strict_shifts` ещё и во время смены;
- сообщения о смене (вечером накануне и за N часов до начала) тихими часами не задерживаются;
- каждое срабатывание помечается как отправленное, повторно сообщение не уйдёт.

### 3. Приложение
1. В `docs/js/config.js` замени `YOUR-PROJECT-REF` на ref проекта (адрес `https://<ref>.supabase.co/functions/v1/api`).
2. GitHub Pages: Settings, Pages, ветка main, папка `/docs`.
3. Адрес должен быть `https://...`, иначе Telegram не откроет.

### 4. Бот
В BotFather: `/newapp` или `/setmenubutton`, укажи адрес из GitHub Pages.

### 5. Проверка
Открой приложение из бота. Должна появиться вкладка «Сегодня» с приветствием.
В «Настройках» переключи оформление и перезайди: выбор должен сохраниться.
Если ты администратор, внизу настроек есть карточка с журналом ошибок и списком пользователей.

## Как защищены данные
- Все таблицы закрыты (RLS без политик): с публичным ключом из браузера прочитать нельзя ничего.
- Доступ только через функцию `api`, которая проверяет подпись Telegram на каждый запрос.
- Администратор смотрит данные пользователя только в режиме «только чтение».
- Вкладка «Цикл» для чужого просмотра закрыта, пока владелица не включит `cycle_share_partner`.
  Проверка `assertCycleAccess` должна вызываться в каждом обработчике данных цикла.
- Автоудаление: ночная задача чистит данные старше срока хранения.

## Что уже есть
- Вкладка «Смены»: календарь месяца, смена на одну дату или сразу на несколько (кнопка «Выбрать даты»),
  ночные смены (конец раньше начала), типы смен со своими часами, отпуск и больничный на период,
  напоминания с повтором и «за сколько напомнить».
- Время вводится по часовому поясу пользователя, в базе хранится в UTC.
- Бот-планировщик (`tick`): напоминания и сообщения о сменах приходят в Telegram.
